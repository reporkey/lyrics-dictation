# Device sync adversarial review

Status: resolved; independent final review returned `RESOLVED`.

An independent read-only reviewer examined the completed device-sync worktree after implementation. The review focused on authorization boundaries, pairing-code lifecycle, concurrent membership changes, replacement privacy, snapshot preservation, local recovery, migrations, and user-visible deletion behavior. The implementation agent reproduced each actionable finding, added regression coverage, and returned the final tree for re-review.

## Findings and remediation

| Severity | Finding                                                                                                                                                                                | Resolution and regression evidence                                                                                                                                                                                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| High     | A joining device's old identity-scoped idempotency responses could replay content from the private space that had just been replaced.                                                  | The join batch now turns every earlier response into a content-free conflict tombstone while preserving the current join reservation. Idempotency completion only writes rows still in progress. The integration suite proves the old response cannot be read or reinserted after joining. |
| High     | An earlier local form of migration `0011` used `ON DELETE SET NULL` for a claimed code, so deleting the claimant could make a used code appear unclaimed.                              | Historical `0011` remains unchanged and append-only migration `0013` rebuilds the table with `ON DELETE CASCADE`. Tests inspect the resulting foreign key and exercise claim, leave, delete, then attempted reuse.                                                                         |
| High     | Expiring a member did not increment the shared-space version or invalidate pending codes, weakening the stale-write fence around that membership change.                               | Both scheduled cleanup and request-time expiry now increment the affected space version and invalidate unclaimed codes before removing membership. Integration tests assert the version change, retained active-member data, and rejected old code.                                        |
| Medium   | If a target space locked successfully but the source space was already busy, a failed join could delete an unclaimed code or increment the target version without a membership change. | Target locking now also requires the expected live, unlocked source membership. Code cleanup requires a successful claim. The busy-source test proves the code remains retryable and the target version is unchanged.                                                                      |
| Medium   | A stale generate-code request could delete the former group's current unclaimed code after the requesting identity had already moved.                                                  | The deletion step now checks the identity's live membership in that exact space inside the D1 batch.                                                                                                                                                                                       |
| Medium   | A stale leave/remove target could create an orphan clone or invalidate codes even when its membership no longer matched.                                                               | Clone creation requires the target's live source membership, and code invalidation requires the membership to have moved into the deterministic private space.                                                                                                                             |
| Low      | Privacy copy implied that one inactive device always deletes shared records after 365 days.                                                                                            | English and Chinese copy now distinguish expiration of this device's access from retention by another active paired device and deletion of a private or last-member space.                                                                                                                 |

## Final acceptance

No Critical, High, Medium, or Low finding remains open. The independent reviewer re-read the final remediations and returned `RESOLVED`.

The final local `npm run check` completed successfully with 66 unit tests, 41 Worker/D1 integration tests, and 38 Chromium end-to-end and accessibility tests, followed by the production build, a zero-finding high-severity runtime dependency audit, and Wrangler deployment dry-run. No deployment was performed.
