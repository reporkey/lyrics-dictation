# Architecture and data model

## Request and persistence flow

The Cloudflare Worker serves static SPA assets and handles `/api/*` first. A first API request creates 32 random bytes, returns the base64url credential in an HttpOnly cookie, and stores only its SHA-256 hash. The UI waits for bootstrap before enabling routes that can mutate data, avoiding concurrent first-request identity fragmentation.

The React client keeps server data in a small context. Successful mutations refresh current state and signal sibling tabs with `BroadcastChannel`; visible dictation tabs revalidate only when they have no unsaved local text. Language, theme, and card/list layout preferences use safe local-storage access plus a separate cross-tab channel. Language follows the first supported browser preference and theme follows the operating system until the user makes an explicit choice. Explicit locale selection is also versioned in D1, so clearing browser storage does not silently overwrite it with a newly inferred default. D1 remains authoritative for saved content. Cookieless bootstrap is serialized across same-origin tabs with the Web Locks API and a local-storage lease fallback, preventing two first visits from minting competing identities. If storage is unavailable, preference changes remain usable for the current page and direct bootstrap provides a degraded single-tab fallback. During dictation, each accepted editor change is written immediately to IndexedDB, graded locally in a Web Worker, and cloud-saved once after 900 ms. A `pagehide` keepalive write is best effort; IndexedDB remains the durable browser defense. Recovery records are deleted transactionally only when the server acknowledges that exact text snapshot. Any valid unmatched record therefore wins on reload, regardless of wall-clock ordering, and is explicitly labeled not synced until D1 confirms it. Submitted sessions are browsed from a dedicated history route backed by owner-scoped `(updated_at, id)` keyset pagination; each row derives accuracy from the four final grading counts and duration from the saved timestamps.

## Tables

- `identities`: UUID primary key, unique credential hash, creation/last-seen/expiry times.
- `settings`: one locale, explicit-choice flag, and version row per identity.
- `songs`: owner-scoped title, artist, editable normalized source, parsed study text, source kind, version, timestamps.
- `sessions`: owner and song, one partial unique in-progress row per song, draft, grading counts, state, version, timestamps.
- `idempotency_keys`: identity/operation/key response records retained for seven days.
- `rate_limits`: identity and named fixed-window counters.
- `session_start_locks`: short-lived per-song leases that serialize overlapping start/restart requests.
- `revoked_credentials`: hashes of deleted credentials retained beyond their possible cookie lifetime, preventing a stale cookie from recreating the deleted identity.

Foreign keys use cascading deletion. Common owner/time lookups are indexed. All statements are parameterized. D1 batches are used where a group must be committed atomically within D1's supported API.

## Grading

Source is normalized and segmented into extended grapheme clusters. Each original grapheme projects only Unicode letters, marks, and numbers; all Unicode whitespace, line breaks, punctuation, symbols, and presentation wrappers are neutral. The only neutral format controls are those belonging to a complete Unicode Emoji 15.1 RGI grapheme, recognized by the pinned `emoji-regex@10.3.0`; arbitrary joiners, tags, selectors, and modifiers are rejected. The filtered stream is canonically ordered as a whole, default case-folded when appropriate, canonically ordered again, and segmented for Levenshtein alignment. Per-code-point provenance survives whole-stream reordering and maps final judged tokens back to every contributing indivisible source grapheme for decorations.

Exact equality has a fast path. Otherwise common prefix/suffix matches shrink the exact matrix. Oversized regions use a deterministic longest non-crossing chain of tokens that occur exactly once in each side as chunk anchors, then refine each chunk. Because heuristic anchors are not proof of a globally optimal edit path, anchored output remains marked non-exact. Ordinary work uses a 750,000-cell worker budget, then progressively refines to 8,000,000 cells. Above 50,000 source scalars, the browser first performs a linear whole-stream equality projection: an equal draft can submit exactly; a divergent draft gets bounded, exact feedback for the first 20,000-scalar window and remains visibly “Checking…” for the unrefined remainder. This avoids constructing maximum-size decoration/provenance objects while still showing useful feedback. The server does not grade autosaves; it stores text/version only. Every terminal action is a submission, whether or not the lyrics are fully recalled. Submission records bounded final aggregates: exact common prefix/suffix matches plus deterministic positional substitution/insertion/deletion counts for the remaining middle. Correctness is represented by those counts and the derived accuracy, never by a separate unfinished result state.

Run `npm run benchmark` to measure short mixed text, long near-match, repetitive omission, totally different bounded work, and a large equivalent paste on the current machine. Benchmark output is environment-specific and is not used as a brittle CI threshold; browser responsiveness is protected structurally by the worker boundary and tested behaviorally.

Local final baseline on 2026-08-29 (arm64 macOS 26.5.1, Node 26.4.0, Vitest 4.1.11): short mixed edit 0.024 ms mean, long near-match 2.82 ms, repetitive omission 0.67 ms, totally different bounded refinement 1.69 ms, large equivalent paste 9.44 ms, a maximum-size 100,000-versus-100,000 divergent authoritative completion check 9.89 ms, and maximum-size abandonment aggregates 19.24 ms. These are domain-function timings, not network or render timings.

The conformance fixtures target Unicode 15.1 semantics. JavaScript `Intl.Segmenter` and Unicode property escapes ultimately use the deployed workerd/browser Unicode data, so runtime upgrades remain a compatibility risk; fixtures are the guardrail until segmentation data is fully vendored.

## API contracts

All writes require a matching `Origin`, JSON content where applicable, and the server-resolved identity. API middleware applies private security headers, rejects cross-origin writes, and only then resolves or creates identity, preventing a rejected cross-site request from rotating the anonymous credential. JSON transport is capped at 1 MiB: a known oversized `Content-Length` is rejected before reading; an unknown/chunked stream uses a fixed-size allocation and is canceled as soon as the bound is crossed. Invalid attempts consume the relevant identity rate buckets. Mutable rows use positive integer versions; stale writes return `409 VERSION_CONFLICT`. Song/session creation, every session save/submission mutation, and song deletion require credential-scoped idempotency keys; the client automatically retries one lost response with the same key and retains a logical UI intent key across manual retry. The operation namespace includes a SHA-256 request fingerprint, preventing a reused key from replaying a response for different content or a different target. Repeated keys for the same logical request replay the stored JSON response. Creates use deterministic credential/operation/key-derived record IDs, and an ambiguous status-0 reservation reconciles against the resulting song/session/version before replay. Unknown post-mutation failures retain their reservation rather than permitting a duplicate; deterministic validation failures release it. Per-song start leases coalesce truly overlapping start/restart work and the database partial unique index remains the final invariant. The legacy `abandon` API action remains accepted for already-open clients and retains its compatibility status so an old UI cannot mislabel an imperfect submission as fully correct; current clients treat every non-active status as a result and never expose that internal distinction.

Delete-all synchronously blocks all ordinary API and recovery writes in every tab, persists a marker in the `server` stage, then calls the sole deletion-only API bypass. The marker is written independently to a small IndexedDB store and, when available, local storage. D1 atomically records the credential hash in `revoked_credentials` and deletes the identity; the response expires the cookie with an absolute past `Expires` value. A stale or racing request carrying that credential is rejected without creating an identity or renewing a cookie. After server success, the marker advances to `local`; IndexedDB recovery and accessible preferences are cleared independently before both marker copies are removed. Reload resumes whichever stage remains, including when `BroadcastChannel` or local storage is unavailable. This state machine prevents navigation, page lifecycle writes, peer tabs, or a partial browser-storage failure from silently undoing deletion.

Rate limits are fixed windows defined in `src/lib/constants.ts`: 120 mutations/minute, 20 imports/hour, and 10 destructive actions/hour. A rejection returns `429` and `Retry-After`.
